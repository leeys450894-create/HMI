## Align Recipe (`.alg`) — 메인 레시피 버저닝과 별개 (2026-09-04 정리)

Glass/Probe SW Align 위치·CCD 설정은 메인 `.rcp`가 아니라 **`D:\HBS\Recipe\ALIGN_RECIPE\*.alg`** (버전 없는 순차 텍스트)에 저장된다. 저장 `AlignRcpDlg::SaveMntFile`, 로드는 `InRecipeFunc.cpp`/`OutRecipeFunc.cpp`의 align 로드 함수(2벌 동기). UI 그리드 `m_gridGlassAlignData`/`m_gridProbeAlignData`, CCD 설정은 `m_gridCcdSetMntData`(IDC_GRID_6: EXP.TIME/GAIN/LED/MAT.SCORE × GLASS L/R, PROBE L/R).

- **블록 순서**: `_GLASS_ALIGN_` → `_PROBE_ALIGN_` → `_CCD_SET_`(수치) → `_CCD_SET_`(패턴 파일명) → `_CENTERING_MARGIN_` → `_SUB_Z_`(꼬리). **필드 추가는 버전 게이트가 아니라 꼬리 블록 + 헤더 문자열 EOF 감지**(`ReadString`이 `_SUB_Z_`를 못 읽으면 구파일 → 구 `m_fFrontZ/m_fBackZ`를 양쪽 SubZ에 복사). 새 블록도 이 방식으로 꼬리에 붙일 것.
- **Glass 블록 인덱스**: [3]`m_fStageY`→AXIS_X, [4]`m_fStageRotate`→R, [5]`m_fFrontY`→X2, [6]`m_fFrontRight`→**AXIS_Y1**, [7]`m_fFrontLeft`→AXIS_Y2, [8]`m_fFrontZ`(구 Z1, 이제 미사용). Probe도 동형이며 [7]이 `m_fStageY`(SUB Z 추가로 한 칸 밀림).
- **SUB Z 매핑(고정)**: `AXIS_Z3` = SUB Z RIGHT = `m_fSubZRight`, `AXIS_Z4` = SUB Z LEFT = `m_fSubZLeft`. 구 `AXIS_Z1`(BACK Z, OCP USE0) 자리는 GET_POS/MOVE(`RecipeEditMgr`, `MaintControlMgr::MoveCmdAlignPos_*`), `DoWorkGlassSWAlignStep::MoveAlignPosition`, `DoWorkProbeSWAlignStep::Align_MovePosition` 모두 Z3+Z4 순차 이동으로 교체됨. Probe 쪽은 2026-09-05에 분기(화상/시야각) 없이 갠트리 MotionDone 후 Z3→Z4로 통일했고, 진입부의 `AXIS_Z2`(FRONT Z) 후퇴 이동도 제거 — Probe Align 이동은 Glass와 동일하게 **X2 / Y1,Y2 / Z3,Z4만 사용**(Z1/Z2 미사용). 단 `bProbeChange==true`(프로브 교체 자세) 분기는 여전히 X3/Y3/Y4를 쓴다(미확인).
- **Y1/Y2**: GET(현재값 읽기)과 MOVE의 Y1/Y2가 교차되어 있던 것을 `MoveCmdAlignPos_*`의 `stPosition[].dPosition`을 바꿔 맞춤(2026-09-04). 축 NAME은 그리드 라벨만 바꾸고 `Config_Motion_ACS.dat` NAME은 손대지 않는다.
- **CCD_SET 함정**: exposure `0`은 16µs로 클램프되어 **거의 검은 영상 → 패턴 서치 실패**. gain은 [300,850] 클램프. 라이브 영상이 보이는데 align이 안 되면 먼저 이 값을 본다(기본 참고값 exp 9000 / gain 400 / score 700). 레시피 `MatchScore`는 실제 판정에 안 쓰이고 코드 하드코딩(500/1000)이 적용된다.
- **Align XYR 오프셋은 "잔차"여야 한다 (2026-09-05 수정).** `SetGlassAlignXYR(X,Y,R)`은 `m_dAlignOffset[AXIS_X]`, `[AXIS_Y1..Y4]`, `[AXIS_LOADER_R]`에 들어가 **모든 `MoveCmdPosA/Multi` 목표에 더해지고 `GetCurPos`에서 빠진다**(`MaintControlMgr` 301/552/589행). 측정 레시피 셀 좌표(`m_fCellX` = Y1/Y2 목표)는 글래스 중심=0인 **절대 기계좌표**(±641 등)이므로 오프셋은 센터링 이동량(수십 µm~수 mm)이어야 한다. 구 코드는 `GetOrgPos(AXIS_Y1) - m_fBase_FrontRight`(base는 어디서도 set/load 안 되는 죽은 필드=0)라 Y1 **절대위치 556.4**가 그대로 오프셋이 되어 셀 목표가 +556mm 밀렸다(Y1 MX 950 초과). 2026-09-05에 `AlignGlassXYZero`/`Align_ProbeXYZero` 진입 시 `GetOrgPos` 캡처 → `최종-시작` 잔차로 교체(R·probe X는 원래 잔차였음). Probe Y용 `m_dGlassAlignOffset[1]-m_dProbeAlignOffset[1]` 차분식은 잔차−잔차로 그대로 유효. 정렬 실행 후 `AlignGlassXYZero residual` 로그의 절대값이 마진(0.1) 수준인지 확인할 것.

### 수동 Align 실패 후 "프로세스 진행 중" 잠김 (2026-09-16 수정)

레시피 Align PROC·Manual 화면·초기화/흡착/프로브교체가 부르는 **`CDoWorkGlassSequenceEngine::ItemStart(형식, true)` 는 항목이 실패해도 결과를 보지 않고 `true` 를 돌려줬다.** 실패한 항목은 None 스텝에서 내린 `m_bComplete` 가 false 로 남고(성공 경로만 `SetComplete(true)`, Glass Idle 은 실패면 건너뜀), `CSequenceManager::IsEngineCompleteAll()` 이 계속 false 가 되어 **이후 모든 레시피 명령(`RecipeEditMgr::ThreadRun` 게이트)과 Maint 모션 명령이 "프로세스 진행 중 입니다" 모달에 막혔다.** 그 모달은 `RecipeEditMgr` 워커 스레드에서 `DoModal` 되어 메인 창 뒤에 숨기 때문에 화면은 무응답처럼 보이고, 복구는 재기동뿐이었다(09-16 19:29 Glass Align 3301 실패 → 19:30 재기동, 19:32·19:34 Probe TZero 6003 실패 → 19:33·19:34 재기동). 자동 사이클의 엔진 루프는 2023.08.23 부터 실패 시 알람 + `SetComplete(true)` 를 하고 있었고 수동 경로만 빠져 있었다.
- 수정: `ItemStart` 가 완료 대기 후 `GetFail()` 이면 `CAlarmController::SetAlarm(GetFailNum())` + WARN(`Seq Item : … - Fail Exit (alarm n)`), 사용자 정지/미완료도 WARN 을 남기고, 세 경우 모두 `SetComplete(true)` 뒤 **`false` 반환**. `RecipeEditMgr` 의 GLASS/PROBE PROC 는 그 반환값으로 `M_RUN_NG` 를 DLL 에 응답(구 코드는 무조건 `M_RUN_END`), 게이트 거부 시 `Recipe cmd n rejected - ProcessStatus=…, EngineCompleteAll=…` WARN 을 OCP 로그에 남긴다. 다른 호출부(`SystemInitializeStep_ProbeAlign`, `DoWorkGlassAdsorptionStep_ProbeAlign`, `ProbeACCStep_Align`, `DlgSubManual_Meas`)는 이제 `bRet` 가 실제 결과라 실패 시 그 자리에서 멈춘다(전에는 실패해도 계속 진행).
- 정렬 알람 ID: `VISION_ALIGN_DETECTED_FAIL`(6002) / `VISION_ALIGN_CENTERING_FAIL`(6003), 이동 실패는 모션 반환값(예 3301) 그대로. `Alarm.xls` 에 6002·6003 행 있음(2026-09-16 사용자 확인). 이 파일은 BIFF 바이너리라 `grep`/바이트 검색으로 ID 유무를 판정할 수 없다 — 사용자에게 열어 확인을 요청할 것.

## Probe Align 보상 경로 (2026-09-05 정리)

**PROBE ALIGN 저장값 ↔ 축 대응은 이름이 뒤집혀 있다 (2026-09-12 확인).** `S_ProbeAlign`의 필드명과 실제 축이 서로 엇갈리므로 이름만 보고 고치면 안 된다:

| Align 레시피 필드 | 그리드(행3) 열 | `m_fData[]` | 실제 축 |
|---|---|---|---|
| `m_fProbeY` | 0 | [0] | **`AXIS_PROBE_X9`** (PROBE GANTRY X) |
| `m_fProbeX` | 1 | [1] | **`AXIS_PROBE_Y5`** (PROBE CROSS) |
| `m_fBackY` | 2 | [2] | `AXIS_X2` |
| `m_fBackLeft` / `m_fBackRight` | 3 / 4 | [3] / [4] | `AXIS_Y1` / `AXIS_Y2` |

| `m_fStageY` | 7 | [7] | `AXIS_X` |

- 저장은 `.alg`의 `_PROBE_ALIGN_` 블록(꼬리 `_SUB_Z_`에 Z3/Z4). UI ↔ 구조체 ↔ 파일은 `AlignRcpDlg::Set/GetProbeAlignData`, `Set/GetProbePos`, `InRecipeFunc`/`OutRecipeFunc`가 모두 대칭이다 — **여기는 정상**이다.
- **MOVE 버튼**(`M_CMD_PROBE_MOVE` → `CMaintControlMgr::MoveCmdAlignPos_Probe`)은 프로브 Z→0, 프로브 X, 프로브 Y, 헤드 Y1/Y2, X2/X3, Z3/Z4 순으로 저장값 전부를 이동시킨다. 2026-09-12 로그로 정상 동작 확인(`MoveCmdPosM Move(AXIS:PROBE CROSS, POS:-5.110 …)`).
  - **목표와 현재가 같으면 수십 ms 만에 끝나 "안 움직인다"로 보인다.** GET_POS로 현재값을 받아 저장한 직후 MOVE를 누르면 항상 이렇게 된다 — 고장으로 오인하지 말 것.
  - **2026-09-17부터 MOVE 의 헤드 Y1/Y2 와 프로브 Y5 는 Glass Align 보상 없이 레시피 값(엔코더)으로 그대로 간다.** 구 코드는 `MoveCmdPosMulti` 라 Y1/Y2 에 `m_dAlignOffset[Y1/Y2]`(Glass Align Y 잔차), Y5 에 `(GlassY − ProbeY)` 가 더해져 레시피 좌표와 실제 위치가 어긋났다. `MoveOrgPosMulti` 로 바꿨고, 짝이 되도록 `M_CMD_PROBE_GET_POS` 도 Y5/Y1/Y2 를 `GetOrgPos`(엔코더)로 저장한다(PROC 의 `Align_MovePosition` 은 원래부터 Org 계열). **X9 는 종전대로**(`GetCurPos`/`MoveCmdPosMulti` 쌍, `m_dProbeAlignOffset[0]` 가산) — GET→MOVE 왕복은 일치하지만 엔코더값과는 프로브 X 잔차만큼 다르다. **MOVE 후 메인 화면 모션 그리드의 Y1/Y2 값이 레시피 값과 Glass Align Y 잔차만큼 어긋나 보이는 것은 정상이다 (2026-09-17 확인)** — `DlgMainForm` 그리드는 `CMaintControlMgr::GetCurPos`(엔코더 − `m_dAlignOffset[axis]`, 레시피 좌표계)를 표시한다. 예: 14:37 Glass Align 잔차 Y −0.1588 → MOVE 지령 −719.030(모션 로그 `MoveCmdPosM Move`)인데 화면은 −718.8712. 실제 엔코더는 Align 레시피 GET_POS(`GetOrgPos`) 또는 Maint 모션 파일 화면(`CMotorControlMgr::GetCurPos`)으로 확인할 것.
  - `GetProbe() < df_PROBE_AGING1`이면 **로그 없이 아무 축도 안 움직이고 return** 했다. 2026-09-12에 진입 로그(`MoveCmdAlignPos_Probe ENTER iProbe=… ProbeX9=… ProbeY5=…`)와 SKIP 경고를 추가했다. 프로브 콤보 기본값은 index 4 → `SetProbe(5)` = `df_PROBE_MEAS`.
