- **설비 내부 프로브 ID(Unload 영역, `m_szUnloadProbeCardID`)는 D2100 6블록 = [0] EQ Unload Data + [1..5] Probe Module #1~#5 이고 현 설비는 [5](D2150, P5)만 유효하다 (2026-09-16 정리).** 앱 `GetIOModuleProbeACC` 가 `szProbeInfo[17]` → `m_szPROBEID[4]` 로 넘기고, OCP 면 `[13..16]`(P1~P4)을 비워 DLL 'PROBE ID' 스프레드에는 5행만 남는다. **이 PLC 는 빈 ID 를 공백 10자(0x2020×5워드 + 0x0000×5워드)로 둔다** — 구 파서는 뒤 5워드의 0 을 `'0'` 으로 바꿔 `TrimRight` 가 공백을 못 지웠고, 그 `"          "` 이 `m_szPROBEID[4]` 까지 흘러 `IsEmpty()`/`_tcslen()` 판정이 항상 "프로브 있음", Probe Align 레시피명이 `PROBE_MEAS_  ` 가 됐다. 09-16 에 `UpdateProbeID` 가 10자 절단 후 `Trim()` 해 빈 ID 를 `""` 로 저장하고(Load 쪽 `0000000000` 은 그대로 = 빈 슬롯), 생성자의 더미 `TEST1~TEST5`(첫 응답 전 P1~P5 에 프로브가 있는 것처럼 보이던 값)와 버퍼 더미 `21ABCDEDFH`(`m_szProbeCardBF[0]` → 버퍼 1 에 프로브가 있는 것처럼 보이던 값)도 제거했다. **살아 있는 SACC 시퀀스의 프로브 유무 게이트는 ID 문자열이 아니라 센서 비트(`IsProbeExistSensorOn/Off`, `PLC_R_PROBE_UNIT05_CARD_CHK_01~04` = M4306~4309)이고, `IsProbeExistSensorOn` 은 2026-09-09 임시로 항상 true** 라 ID 가 비어도 로드/언로드는 막히지 않는다. ID 문자열이 실제로 쓰이는 곳은 ① SACC 화면 PROBE ID 표시, ② `Probe_Mount/Unmount` 이력, ③ 자동 사이클 `CDoWorkGlassRecipeStep_ProbeCheck`(레시피 `_PROBE_ID_` 5번째 값이 비어 있지 않을 때만 D2150 과 비교 → 다르면 카세트에서 그 이름을 찾아 교체, 못 찾으면 사이클 FAIL — 현재 레시피들은 5번째 값이 비어 있어 skip), ④ Probe Align 레시피명 `PROBE_MEAS[_앞2자]` 뿐이다. 수동 장착 프로브는 D2150 에 ID 를 넣는 경로가 없다(RFID 는 SACC 로봇 쪽 PLC 가 D2400 EQ Load Data 에 쓰고, HMI 는 로딩 시퀀스의 `SetProbeloadData` 에서 그 값을 D2150 으로 복사할 뿐). **언로드 시 `SACCPutReq`/`SACCExChangeReq` 가 `m_szPROBEID[4]` 를 D2100 에 써 주고 PLC 는 이 값을 로봇 동작에 쓴다(2026-09-16 사용자 확인)** — 수동 장착 상태로 언로드하면 빈 값이 가므로, **수동 장착 후 SACC 언로드 전에는 반드시 D2150 에 ID 를 등록해야 한다.**
- **수동 장착 프로브 ID 등록 (2026-09-16 구현, 빌드·재기동 대기).** SACC 화면 EQ Inside 스프레드 아래 입력칸 + `SET ID` / `CLEAR ID`(`IDC_EDIT_EQ_PROBEID` 1290 / `IDC_BTN_SET_PROBEID` 1291 / `IDC_BTN_CLEAR_PROBEID` 1292). 경로: DLL `CDlgSACC::SendManualProbeID` → `RITEMDATA{nEventCmd = SACC_COMMAND_OPERATION_SET_PROBEID, nWTSequence = 프로브(5), szText = ID}` → `CSACCMgr::OnControlMsgReceive` → `CFunctionModuleEQState::SetEQManualProbeID(probe, id)` 가 `D(2100+10*probe)`(P5 = D2150) 에 10자 쓰기(빈 문자열 = 공백 10자 = 빈 ID). **`RITEMDATA` 끝에 `szText[32]` 를 추가했으므로 `API_SACC.h` 2사본(`Source/Include/`, `CoreFunction/dSACC/`)을 항상 동일하게 유지할 것**(포인터로 프로세스 내 전달이라 DLL·앱 둘 다 리빌드하면 됨). 입력 검증: 1~10자, 공백·쉼표 없는 인쇄 가능 ASCII, 대문자 강제, SACC 시퀀스 진행 중(`PLC_PACC_PACC_ALL_SEQ_DONE`=0)이면 거부. **보호 장치**: `CFunctionModuleProbeACCStep_SACCPutReq`/`_SACCExChangeReq` 진입 시 `m_szPROBEID[probe-1]` 이 비어 있으면 D2100 을 쓰지 않고 `return false` + `SEQ SACC` WARN `SACC unload/exchange blocked - EQ probe ID empty …`. 로그는 전부 `SEQ SACC_*.log`(`SACC SET_PROBEID probe=5 D2150 id=[..] -> OK`) — `CFunctionModuleEQState` 자체 accessor 는 `Initialize` 되지 않아 쓰지 않는다. 운영 절차: 수동 장착 → SET ID → 약 5초 뒤 스프레드 5행에 표시 확인 → 언로드/교체. 수동 탈착 시 CLEAR ID. 레시피 `_PROBE_ID_` 5번째 값을 쓰면 등록 ID 와 같아야 자동 사이클 프로브 검사가 통과한다.
- **ProbeCard 스캐너 로그(`Logs\Control\IOControl\LogFile\ProbeCard_*.log`) 형식이 2026-09-16 에 바뀌었다.** 읽기 직후 줄은 `ReadProbeXData send(1) D2400 x80 words` 처럼 송신 사실만 남기고, **실제 수신 값은 파싱 직후 `RECV ProbeLoadData(D2400 EQ Load, CST1~7) : [..], [..]…` / `RECV ProbeBufferData(...)` / `RECV ProbeUnloadData(D2100 EQ Unload, P1~P5) : …`** 로 남는다(구 형식은 응답 전에 찍어 항상 직전 주기 값이었다 — 기동 로그의 `TEST1~5` 가 그 흔적). 응답 헤더(기대 길이 포함)가 안 맞으면 `UpdateProbeID(type n) header mismatch - expected len … end code [..]` WARN 이 내용 변경 시 1회 남고 옛 값이 유지된다(PLC 가 D 범위 오류 코드를 돌려주는 경우 등). 연결이 끊기면 `ProbeCard scanner disconnected - … cleared` WARN 1회와 함께 세 ID 배열이 비워진다. 빈 ID 를 만드는 쪽은 `FunctionModuleEQState::SetEQClearPrboeData`(D2100/D2150 에 0 문자열 10자 쓰기)이며, 기록은 로딩 시 `SetEQGetPrboeData(4)` 가 `m_szLoadPROBEID`(D2400 EQ Load Data) 를 D2150 에 쓴다 — 수동으로 장착한 프로브는 D2150 이 비어 있으므로 "EQ 에 프로브 있음" 판정이 거짓이 되는 것이 정상 동작이다.

## Test Mode 다이얼로그 (레시피 DLL 안에 있다 — 2026-09-16 정리)

레시피 화면의 TEST MODE 버튼이 여는 `IDD_DLG_TEST_MODE`는 **`CoreFunction/dll_Recipe/dfcRecipe/DlgTestMode.cpp`(DLL)** 이다. `Source/ALPHA/DlgTestMode.cpp`도 있지만 **`ALPHA.vcxproj`에 들어 있지 않은 죽은 사본**이라 고쳐도 아무 일도 안 일어난다. DLL은 모션·카메라에 직접 접근하지 못하므로 **공유 메모리 `m_sRunState`에 `M_CMD_TEST_MODE` + `m_dwData2`(서브 커맨드)를 채우고 `WM_RECIPE_EVENT`/`M_RCP_TEST_MODE`를 부모(`C_RecipeMgrDlg`)에 포스트 → 앱 `CRecipeEditMgr::ThreadRun()`의 `case M_CMD_TEST_MODE` 가 실행**한다(워커 스레드라 블로킹 이동 가능). 서브 커맨드: 0 MOVE · 1 PRE_CONTACT · 2 CONTACT · 3 UNCONTACT · **4 SAVE_IMAGE · 5 CAM_JOG (2026-09-16 추가)**.
- 컨트롤은 `dfcRecipe.rc`(UTF-16LE, CRLF) 템플릿에 정의되고 ID는 DLL `resource.h`의 범용 `IDC_BUTTON_n/IDC_RADIO_n/IDC_GRID_n`을 쓴다. 09-16 추가: `Save Image`=`IDC_BUTTON_1`, `CAM_Both/Left/Right`=`IDC_RADIO_5~7`, 조그 그리드=`IDC_GRID_2`(0행 헤더 Move/REL/<</>>, 1행 MOVE/상대거리(편집)/−/+). **`DlgTestMode.cpp/.h`는 이 저장소에서 드물게 LF 줄바꿈**이라 Perl 앵커에 `\r\n`을 쓰면 안 맞는다.
- **Save Image**: 앱이 `pAlignCameraMgr[0]`(=CAM_LEFT, Y2 헤드)·`[1]`(=CAM_RIGHT, Y1 헤드)에서 `SnapImage` 후 `<RESULT_PATH>IMAGE\TEST_MODE\yyyy-mm-dd\CAM_LEFT|CAM_RIGHT\yyyymmdd_hhmmss.png` 로 저장. 카메라 index↔좌우는 Align 레시피 CCD 설정(`m_sFrontLeft`→index 0, `m_sFrontRight`→index 1)과 같은 규약. 로그 `TestMode SaveImage …`(OCP 로그).
- **CAM_JOG**: Review/WAD 선택 시 Y1/Y2(BACK), VISION/ANGLE 시 Y3/Y4(FRONT). CAM_Left=Y2/Y4, CAM_Right=Y1/Y3, Both=둘 다 같은 상대량. `MoveCmdPosR(…, false, SPEED_LOW)` 두 축 지령 후 `DoWork_MotionDone`. |거리| 0.0005 미만·100mm 초과는 앱에서 거부(`TestMode CamJog SKIP`). 헤드 간격 인터락은 모션 계층 `MoveCmdPosR_Sub`가 그대로 적용.
- **MOVE(서브 0)의 2026-09-18 변경 2건 — 둘 다 앱 쪽 `CRecipeEditMgr` `case M_CMD_TEST_MODE` / `case 0` 안이고 DLL 은 무관.**
