## 1. Aging 회차 결과 슬롯 — 검증 결과 정리 (2026-08-14)

지난 주 구현한 R1(회차별 결과 행 블록 분리) / R2(회차별 InnerID 재생성)에 대한 사이클 검증을 마치고, 결과를 `AgingResult_RepeatSlot_Plan.md` §5.0에 정리했다.

| 검증 항목 | 방법 | 결과 |
|---|---|---|
| 하위호환 (Aging 미사용) | `m_bUseAging_Test=0` 사이클, 결과 행 산식 비교 | 기존과 동일 (오프셋 0) |
| 회차별 행 분리 | `LogAgingRow` 진단 로그로 회차별 행 번호 추적 | 블록 단위 `nArea × nMaxStick` 로 정상 분리 |
| InnerID 중복 | 회차 간 InnerID 공유율 측정 | **306/306 중복 0** |
| 스틱 매핑 | AgingRcp `[MASECELL]` 대 실제 측정 스틱 대조 | rotate=2 에서 1:1 (반전 없음) 확정 |
| MultiPoint × 회차 | 블록 오프셋 충돌 검사 | 충돌 없음 |

**InnerID 중복 해소 경위:** 1차 수정은 `SetMeasureArea()`에 캐시 clear를 넣었으나 이 함수가 **스틱마다** 호출되어 16건 중 4건이 잔존했다. 생명주기 훅 의존을 버리고 발급 이력 롤링 윈도우(`m_vecIssuedInnerID`, 512개)로 전환하여 해결.

**측정 한계:** OOS(Out of Service) 환경에서는 `TossResultFile`이 가드에 막혀 dResult에 기입되지 않아 APD.txt가 항상 비어 있다. 따라서 APD 파일 diff는 검증 수단으로 사용할 수 없고, InnerID 공유율과 진단 로그로 대체했다.

## 2. Cell 선택 다이얼로그 Stage 180°(단변) 대응 (2026-08-18)

### 2.1 문제

`IDD_SELECT_CELL_DLG`(Sampling 대상 Cell 선택)와 `MakeCellDlg`(Cell 맵 생성)가 Stage 90°(장변)만 고려하여 작성되어, 단변 레시피(180°)에서 Cell 좌표계가 어긋났다.

### 2.2 수정

| 파일 | 변경 내용 |
|------|----------|
| `dfcRecipe/preDefine.h`, `Source/Include/preDefine.h` | `#define RCP_CELL_ANG_180 2` 추가 (이중 사본 동기화) |
| `dfcRecipe/MakeCellDlg.cpp` | 180° 분기 4곳 신설 |
| `dfcRecipe/SelectCellDlg.cpp/.h` | 0° 분기를 `if (rotate == 0 \|\| rotate == 180)` 으로 공유 (레이아웃 재사용) |

**`m_fStageRotate` 값 검토:** 180° 분기에서 `m_fStageRotate = 90.` 이 맞는지 재확인 요청이 있어 실측 대조함. 측정각은 `스틱 m_fStageR + USER OFFSET(m_fStageRotate)` 으로 합산되며, 실제 레시피는 **장변 = 90 + 0, 단변 = 180 + 0** 이다. 즉 스틱 각도에 이미 180이 들어 있어 오프셋은 `0`이 옳으며, 90을 넣으면 단변이 270°로 회전한다. 기존 `= 0` 유지.

### 2.3 UI 추가

Cell 선택 그리드에 **전체 선택 / 전체 해제** 버튼 2개 추가 (`IDC_BUTTON_2` / `IDC_BUTTON_3`, `SetAllCell(BOOL)`).

> Sampling 옵션이 꺼진 경우 전체 Cell을 검사하는 기존 동작은 그대로 유지하기로 확정.

### 3.2 START 사전 점검

## 4. WAD Multi Meas — bOneCell 폐지 / REPEAT 컬럼 이관 (2026-08-18 ~ 08-19)

### 4.1 배경

결과 시트 6열 `REPEAT` 를 "재시도 횟수"로 해석했으나, 실제로는 **`bOneCell` 기능이 소비 중인 컬럼**임이 확인되었다. `bOneCell` 은 더 이상 사용하지 않는 기능이며 Multi Meas 로 대체 예정이므로, 해당 컬럼을 다중측정 포인트 번호로 이관했다.

작성 문서:
- `docs/Result_Identification_MES_Agreement_Plan.md` — MES 협의안 (Q1~Q6, D1~D3)
- `docs/OneCell_To_MultiPoint_Migration_Plan.md` — 이관 플랜 및 구현 결과

### 4.2 구현

| 파일 | 변경 내용 |
|------|----------|
| `Source/ALPHA/CommTcpIpObjectWAD.cpp` | `nPointNo` 도입 — 기본점도 1로 채번, 오프셋 조회 인덱스와 분리. `resultData.nMultiPoint` / `m_iRetryCnt`(6열 REPEAT) 에 기입 |

### 4.3 1/3 지점 미측정 문제

사이클 로그 판독 결과 `기본 측정 → 1/3 → 2/3 → 3/3` 중 1/3 지점이 누락되었다. 원인은 오프셋 조회 인덱스와 포인트 번호를 같은 변수로 쓰면서 기본점(1)과 1/3 지점(1)이 충돌한 것. `nPointNo` 분리 및 `SetRunPointIdx(p, 0)` / `SetRunPointIdx(p, ip)` 명시로 해결. 이후 로그 표기(base = `point(base)`, multi = `nRunCnt - 1`) 정합도 함께 맞춤.

**잔여:** REPEAT 컬럼의 실제 기입 값은 OOS 환경에서 확인 불가 — 실기 검증 필요.

## 5. ANGLE 축 10개 추가 대응 (2026-08-19)

시야각 측정 모듈용 축 10개(`ACS1/ACR1/ACZ1/AMT1/AMA1`, `ACS2/ACR2/ACZ2/AMT2/AMA2`)가 추가되면서 발생한 문제 해결 및 후속 기능 구현.

### 5.1 실행 시 브레이크 원인 규명

**증상:** `CALPHAApp::InitInstance()` 240행(`dlg.DoModal()`)에서 중단.

**원인:** 축 추가 자체는 정상(enum 89~98, `m_cAxis.resize(100)`, `.dat` `NUM[82]` 정합, `g_iMapAxis` 등록 10개, `ACS[1]` 유효). 실제 원인은 **`stMotorInfo m_stMoterInfo[90]` 배열을 `iAxis` 0~`AXIS_TYPE_END`(99)로 인덱싱하던 기존 결함**이었다. 신규 축이 `USE[1]` 이 되면서 값 기입 경로로 진입, 약 500바이트가 `CDlgMainForm` 후미 멤버를 덮어썼다.

**조치:** `m_stMoterInfo[90]` → `[df_USE_MAX_AXIS]` (`DlgMainForm.h`, `CD_PopUp_Motion_Move.h`), `DlgMainForm.h` 에 `AxisType.h` include 추가.

### 5.2 초기화 홈 시퀀스 편입

`CSystemInitializeStep::MotionHome()` `case 1`(Head Z 광학계 그룹)에 ANGLE 10축 추가 — `MoveHome` 목록과 `CheckHomeDone` 목록 2곳.

> `CSystemInitializeStep_InitMotion` 에도 동일 목록이 있으나 `SystemInitialize.cpp:59` 에서 주석 처리된 **사장 스텝**이므로 수정 대상에서 제외.

**Z3~Z6 선행 홈 신설:** Z3~Z6(enum 20~23)가 **어떤 홈 대상에도 포함되어 있지 않음**을 확인. 기존 광학계 루프는 "전 축 MoveHome 발행 → 역순 CheckHomeDone" 구조라 목록 순서만으로는 선행이 보장되지 않으므로, 자체 MoveHome + CheckHomeDone 을 갖는 **전용 선행 페이즈**를 광학계 루프 앞에 삽입했다.

### 5.3 Maintenance UI 축 표기

`CDlgSubMaint_MotionFile::__RefreshListData3()` 및 `CD_PopUp_Motion_Move::__RefreshListData3()` 의 축 필터 상한 `iAxis < AXIS_PROBE_X1` 이 ANGLE 대역(89~98)을 통째로 차단하고 있었다.

```cpp
(iAxis < AXIS_PROBE_X1 || (AXIS_ANGLE_SF1 <= iAxis && iAxis <= AXIS_ANGLE_AZM2))
```

클릭 핸들러가 Num 컬럼 값을 축 번호로 역참조하는 구조라 HOME/MOVE/± 버튼은 추가 배선 없이 동작한다.

### 5.4 Recipe 파라미터 신설 (V1007)

Angle 모듈 5개 파라미터 × 2모듈 = 10개를 레시피에 추가.

| 파일 | 변경 내용 |
|------|----------|
| `preDefine.h` (2사본) | `S_MotionAngle` 구조체(double 10) + `S_RecipeInfo::m_sMotionAngle` + `RECIPE_FILE_V1007` |
| `dfcRecipe/resource.h`, `dfcRecipe.rc` (UTF-16) | 그리드 4개(`IDC_GRID_ANGLE_HEAD1/DATA1/HEAD2/DATA2` = 10428~10431), 페이지 높이 466 → 545 |
| `dfcRecipe/RecipeMgrDlg.h/.cpp` | DDX 4개, `InitAngleAxis()` / `SetAngleAxis()` / `GetAngleAxis()`, `_ANGLE_AXIS_` Save 블록 |
| `dfcRecipe/InRecipeFunc.cpp`, `OutRecipeFunc.cpp` | `if (nVersion > RECIPE_FILE_V1007)` Load 블록 + `else { Clear(); }` |

**중요 결함 발견:** `S_MotionAngle` 이 `Source/Include/preDefine.h` 에만 존재하고 DLL 사본에는 없었다. `CRecipeEditMgr::GetRecipeInfo()` 가 **DLL 내부 구조체의 raw 포인터를 ALPHA 에 반환**하므로, 이 상태로 두면 컴파일은 통과하고 런타임에 DLL 할당 범위 밖을 읽는다. 양쪽 사본을 동기화하고 diff 로 검증(주석 1줄 외 차이 없음)했다.

**UI:** `PIX_UNIFORMITY` 가 열 폭을 61px 로 고정하여 컨트롤 폭에 남는 여백이 6번째 칸처럼 보이는 현상 발생 → `AngleFitColumns()` 헬퍼로 실제 폭에 5열 균등 분배.

### 5.5 측정 시 레시피 값 적용

ANGLE 측정마다 옵틱스가 레시피 값으로 이동하도록 `MoveCmdPosAngle()` 을 확장했다.

- **호출처** (`CDoWorkGlassMeasureStep_Measure_ANGLE::Run()`): 레시피 값을 `stPosition[7]~[16]` 에 실어 전달, 배열 `[10]` → `[20]`. 레시피에 모듈당 값이 1세트뿐이라 셀마다 달라질 수 없으므로 **전축 이동 브랜치(첫 그룹)** 에만 배치
- **`MoveCmdPosAngle()`**: `AXIS_ANGLE_SF1~AZM2` 처리 분기 신설. **앞에서 지령 / 뒤에서 대기** 구조로 헤드 이동과 병렬 처리하여 추가 택트 없음
- **`bDoneCheck` 무시하고 항상 대기**: 측정 스텝의 자체 대기 루프가 `stPosition[0..1]` 만 커버하므로, 그대로 두면 옵틱스 정지 전에 PG 측정 트리거가 나감
- **가드 2종**: 축별 `bUse` 확인(모듈 미탑재 설비 대응), **값이 0이면 이동 생략**(`fabs < 0.0001`) — 신규 레시피가 전 필드 0.0 인 상태로 Scheimpflug(35~75°) 등을 SW 리밋으로 몰지 않도록 함

## 6. OCP 툴셋 v143 → v142 복원 (2026-08-20)

**문제:** 작업본 OCP 8개 프로젝트가 전부 `PlatformToolset v143` 으로 리타게팅되어 있었다. 설치된 툴셋은 **VS2019 = v142 뿐, VS2022 = v143 뿐** 이므로 VS2019 로는 빌드 불가 상태였다. `Metrosys.vcxproj` 수정일 2026-08-05, `Bin/Metrosys.exe` 빌드일 2026-06-23 — **리타게팅 이후 한 번도 빌드되지 않았음.** VS2022 로 솔루션을 열었을 때 자동 업그레이드된 것으로 판단된다.

**조치:** `<PlatformToolset>v143</PlatformToolset>` → `v142`, **22곳 / 8파일**. 백업본(`A3_OCP_v4.0.4.3_20260521_Build_OK_32Bit`, 21개 프로젝트 전부 v142)과 대조 결과 `WindowsTargetPlatformVersion`(10.0), `ToolsVersion`(Current), `.sln` 헤더(Version 16)는 모두 그대로여서 툴셋만 치환하면 되는 부분 업그레이드였다.

**검증:** `//t:Clean` 후 VS2019 전체 재빌드 성공(Error 0), 산출물 PE 헤더 `0x014c` = **x86 32비트** 확인. 구버전 FPSpread OCX 가 64비트 빌드를 제공하지 않으므로 32비트 유지는 필수 제약이다.

## 잔여 사항 / 주의점

1. **ANGLE 축 실기 검증 필요**
   - Maintenance 화면 하단 그리드 4개 표시 확인 (좌표 계산값으로 배치, 잘리면 y값 조정 필요)
   - TILT/AZIMUTH 부호와 기구 원점 기준 일치 여부
   - HOME 버튼은 확인창 직후 즉시 `MoveHome` + `CheckHomeDone` 실행 — 원점/리밋 방향 검증 전 사용 금지
2. **Z3~Z6 선행 홈 순서** — 현재 `case 1` 최선두라 Z1/Z2 보다도 먼저 수행된다. Z1/Z2 와의 순서 제약이 있으면 위치 조정 필요
3. **ANGLE 축 0 값 제약** — 이동 생략 가드로 인해 이 10축에 0을 목표값으로 지령할 수 없다. Rotate 등 0이 정상 위치인 축은 `0.001` 이상 입력 필요
4. **REPEAT 컬럼 실기 검증** — OOS 환경에서는 dResult 기입이 발생하지 않아 확인 불가
5. **MES 협의 대기** — `Result_Identification_MES_Agreement_Plan.md` Q1~Q6. 특히 Q2(수용 한계, `AREA_MAX_CNT` 2500으로 상향했으나 MES 측 확인 필요), Q3(신규 컬럼 `REPEAT_NO`), Q5(전 회차 vs 최종만)
6. **OCP Release 빌드** — 검증은 Debug 로 수행했고 `Bin/Metrosys.exe` 가 Debug 산출물로 교체된 상태. 배포본이 Release 여야 하면 Release 재빌드 필요
7. **VS2022 리타게팅 재발 주의** — `Metrosys.sln` 을 VS2022 로 열면 v143 업그레이드를 다시 권유한다. 반드시 거절할 것
8. **기존 레시피 호환** — V1007 이전 파일은 Angle 파라미터가 0 으로 초기화된다. 한 번 SAVE 하면 `_ANGLE_AXIS_` 블록이 추가됨
9. **보류 과제** — ANGLE 다이얼로그 이식(통신 사양서 부재), bOneCell 잔여 코드 완전 제거(M3), MultiPoint InnerID 원 의도 복원(R2-4)
