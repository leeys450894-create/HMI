# 측정 결과 행 식별 체계 — MES 협의안

작성: 2026-08-18 (LYS)
관련: [AgingResult_RepeatSlot_Plan.md](AgingResult_RepeatSlot_Plan.md) §7-1, [WAD_MultiMeas_Porting_Plan.md](WAD_MultiMeas_Porting_Plan.md), [AgingCycleEngine_Design_Plan.md](AgingCycleEngine_Design_Plan.md)

## 1. 협의가 필요한 이유

HMI는 **한 셀을 여러 번 측정**하는 기능을 두 가지 갖고 있다.

| 기능 | 반복 축 | 한 셀당 측정 횟수 |
|---|---|---|
| Aging Cycle | 에이징 리스트 아이템(회차) | 아이템 수만큼 |
| WAD Multi Point | 셀 내 측정점 | 활성 점 수만큼 |

두 기능 모두 **결과를 서로 다른 행에 분리 저장**하도록 구현을 마쳤다(2026-08-12, OOS 검증 완료). 그러나 **분리된 행이 각각 몇 회차·몇 번 점인지 표기하는 수단이 현재 HMI에 없다.** 행 번호(`SERIAL`)로 역산은 가능하지만 계산식을 아는 쪽에서만 가능하고, `CELLID`는 회차·점이 달라도 동일하다.

OCP는 이 문제를 결과 시트의 `REPEAT` 컬럼으로 해결하고 있으나, HMI는 같은 이름의 컬럼이 **다른 용도로 이미 점유**되어 있어 그대로 쓸 수 없다. 따라서 **어떤 식별자를 어떤 형태로 APD에 실을지** MES 측 합의가 필요하다.

## 2. 현재 결과 업로드 경로 (양 기종 공통)

```
측정 → dResult FPSpread 시트(행 기입) → 시트 병합 → APD.txt → FTP PUT → 완료 전문 1건
```

- **셀 단위 CIM 전문은 없다.** 글라스 1장당 APD.txt 파일 1개를 FTP로 올리고 완료 전문 하나로 끝난다.
- APD `[RAW_DATA]`는 **한 행 = 한 라인**, 라인 내부는 `컬럼명,값,` 쌍의 나열이다 (`CDlgResult.cpp:2019-2062`).
- 따라서 **컬럼 추가는 형식상 가법적(additive)** 이다 — 기존 쌍의 순서·이름은 유지되고 새 이름의 쌍이 덧붙는다.

## 3. 행 레이아웃 (구현 완료분)

```
행 번호 = 셀오프셋 + 1 + (블록크기 × 블록인덱스)
블록크기 = nArea × nMaxStick          (= 글라스 전체 셀 수)
```

| 종류 | 블록 인덱스 |
|---|---|
| WAD 기본점 | `회차` |
| WAD Multi Point (`ip`) | `종류별_아이템수 + 회차 × (점수-1) + (ip-1)` |
| VISION / ANGLE | 각 종류의 `회차` |

**실측 예** (단변 레시피: 5셀 × 21스틱 = 블록 105, 에이징 3회차 × 다점 3점):

| 구분 | 행 범위 |
|---|---|
| 기본점 회차 0/1/2 | 1~105 / 106~210 / 211~315 |
| 다점 블록 3~8 | 316~945 |

행 충돌 0건, InnerID 중복 0건으로 검증 완료(2026-08-14).

## 4. 문제 1 — 식별 컬럼 부재

### 4.1 OCP 방식 (참고)

결과 시트1에 `REPEAT` 컬럼이 있고, 다점 측정 시 `{회차}_{Class}` 형태로 기록한다.

```cpp
// DlgNaviData.cpp:8550-8560
if (bCheck) { str.Format(_T("%d_%s"), nRepeat + 1, strClass); ... }  // 예: "1_C4"
else        { str.Format(_T("%d"), nRepeat); }                        // 일반 측정
```
`strClass`는 MultiMeas 레시피 `[DATA] CLASS / SUB_CLASS`에서 점별로 가져온 문자열이다(`JOB_Proc.cpp:7840`). 별도로 `SEQUENCE` 컬럼(`MEAS_RESULT_ICP_ITEM`)에 측정 종류를 누적 표기한다(`특`/`화`/`L_1(0)_`).

> OCP 내부 비대칭 1건: 기준점(i==0)은 `SUB_CLASS`, 실측점(i>=1)은 `CLASS`를 넘긴다(`:7856` vs `:8025`). 실제 파일 관례는 CLASS=계열(`C`), SUB_CLASS=점번호(`C1`~`C6`)이므로 실측점이 점 구분 불가 상태로 보인다 — OCP 측 결함 가능성이 있어 그대로 이식하지 않았다.

> **2026-08-18 갱신** — 아래 §4.2의 "REPEAT = 재시도 횟수" 서술은 **오독이었다.** 값의 출처를 추적한 결과 `REPEAT` 컬럼은 처음부터 **측정점 번호**(`bOneCell` 서브 포인트 `k+1`)였고, 인자명 `nRetry`·필드명 `m_iRetryCnt` 때문에 재시도로 보였을 뿐이다. `bOneCell`은 폐지하고 소스를 WAD Multi Point 점 번호로 이관 완료([OneCell_To_MultiPoint_Migration_Plan.md](OneCell_To_MultiPoint_Migration_Plan.md)). **따라서 다점 식별자는 스키마 변경 없이 확보되었고, 신규 컬럼은 에이징 회차용 1개만 필요하다.** 갱신 결과는 §6·§7에 반영했다.

### 4.2 HMI 현재 상태

결과 시트1 헤더는 OCP와 같은 이름을 쓰지만 **실제 값이 다르다.**

```cpp
// CDlgResult.cpp:970  헤더
{ "SERIAL", "CELLID", "COORD X", "COORD Y", "EL_PTP", "REPEAT" }

// :985-988  실제 기입
SetDataString(5, ..., m_iRetryReason);   // 헤더는 EL_PTP
SetDataString(6, ..., m_iRetryCnt);      // 헤더는 REPEAT  ← 재시도 횟수
```

즉 `REPEAT` 컬럼은 **재시도 횟수**로 점유되어 있다. 여기에 회차를 쓰면 재시도 정보를 덮어쓴다.

또한 MultiMeas의 `CLASS`/`SUB_CLASS`는 구조체·파일 왕복·UI 편집까지 이식됐으나 **시퀀스 소비처가 0건**이라 결과에 전혀 반영되지 않는다(`GetPoint()`는 `bEnable`/`dPosX`/`dPosY`만 사용).

### 4.3 결론

**회차 식별(Aging)과 점 식별(Multi Point)은 같은 자리를 필요로 하는 하나의 문제다.** 개별로 결정하면 컬럼 설계가 두 번 바뀌므로 묶어서 협의한다.

## 5. 문제 2 — `AREA_MAX_CNT` 상한

APD 헤더에 `AREA_MAX_CNT`가 **1000으로 하드코딩**되어 있다(`CDlgResult.cpp:1944`).

```
최대 행 = 종류별_아이템수 × 점수 × nArea × nMaxStick
```

| 조합 (단변 5셀×21스틱 = 105) | 최대 행 | 상한 대비 |
|---|---|---|
| 3회차 × 3점 (실측) | 945 | **94.5%** |
| 4회차 × 3점 | 1260 | **초과** |
| 3회차 × 4점 | 1260 | **초과** |

현재 조합이 이미 상한 근처다. **운용 조합 상한을 정하거나 `AREA_MAX_CNT`를 상향해야 한다.**

## 6. 선택지

### 안 A — 신규 컬럼 1개 추가 (권장 · 2026-08-18 축소)

**다점 식별은 기존 `REPEAT` 컬럼으로 이미 해결됐다**(§4.2 갱신 참조). 남은 것은 에이징 회차뿐이므로 컬럼 1개만 추가한다.

| 컬럼명(안) | 값 | 예 |
|---|---|---|
| `REPEAT_NO` | 에이징 회차 (1-base, 비적용 시 1) | `2` |
| ~~`POINT_ID`~~ | **불필요** — `REPEAT` 컬럼이 측정점 번호를 담는다 | — |

- **장점**: 기존 컬럼 의미 무변경, 이름 기반 파싱이라 자기설명적
- **단점**: MES 파서가 신규 컬럼명 1개를 수용해야 함
- **작업량**: dResult 시트 컬럼 추가 + 기입 + 병합/APD 경로 확인. 시퀀스는 이미 회차 인덱스를 갖고 있어 전달만 하면 됨

### ~~안 B — 기존 `REPEAT` 컬럼 정상화 후 재사용~~ (폐기)

`REPEAT`가 원래부터 측정점 번호였음이 확인되어(§4.2 갱신) **재사용이 아니라 정상화**로 정리됐고, 이미 적용 완료다. 별도 선택지로 남길 이유가 없다.

### 안 C — `CELLID`에 접미사 인코딩

`CELLID`를 `A01_R2_C4` 형태로 확장.

- **장점**: 컬럼 스키마 무변경
- **단점**: **비권장.** `CELLID`는 MCR ID(체크섬 포함)로 다른 경로에서도 쓰이므로 오염 위험이 크다

### 안 D — 식별자 미도입 (현행 유지)

행은 분리되어 있으나 식별자는 싣지 않는다.

- **장점**: 변경 0
- **단점**: MES가 `SERIAL`(행 번호)로 역산해야 하고, 계산식이 레시피 구성에 의존한다. 실질적으로 회차·점 구분 불가
